# Release requirements

The current copy is intended for private author review. Public release still requires an author-approved software licence, confirmed software citation metadata, the final repository URL and release identifier, data access information, and an archive of the exact manuscript version. A private GitHub repository alone does not provide access to editors or reviewers: they need an explicitly arranged access route or a submission code package.

Nature Communications requires a Code Availability statement for custom code central to the conclusions, access conditions and licensing information, and relevant software versions and parameters. Its submission guidance asks that central custom code be available to editors and reviewers at submission. The computational-code guidance recommends maintaining the manuscript version and assigning a DOI or other unique identifier; a tagged GitHub version can be archived with Zenodo or another suitable archive.

Sources checked on 16 October 2026:

- [Nature Communications Policy Guide](https://www.nature.com/ncomms/submit/policy)
- [Nature Communications submission guidance](https://www.nature.com/ncomms/submit/how-to-submit)
- [Nature computational code publication guidelines](https://media.nature.com/full/nature-cms/documents/GuidelinesCodePublication.pdf)

Do not replace the manuscript's current availability statement with a claim of public availability until the release is actually accessible and the final identifier exists.
